# Документация

Опубликованные документы по коду лежат в `docs/` под git; рабочие `PLAN.md` и `QUESTIONS.md` — в `.claude/docs/`, вне git. Читай нужный документ целиком, когда задача его касается. Новый документ записывай в этот список в формате `- [назначение](путь): описание`, путь — от корня репозитория; в список попадает только документация по коду.

- [Контракт](docs/CONTRACT.md): устройство системы и решения — роли, агент в коробке, перехват, FUSE, шлюз, протокол (каналы управления и данных по SSH), авторизация.
- [План](.claude/docs/PLAN.md): открытая работа со статусами ⏳ 🔨, нюансы реализации и их решения.
- [Авторизация агентов](docs/AUTH.md): по Claude Code, Codex CLI, Antigravity CLI — вход, хранение, срок, обновление, несколько копий, передача в контейнер; пригодность для Iapetus.
- [Harness агентов](docs/HARNESS.md): как Claude Code, Codex CLI, Antigravity CLI (и Gemini CLI для сравнения) пишут файлы, запускают команды, говорят с API, принимают инструкции и MCP; headless и ACP, условия использования, OpenRouter; сводка по слоям Iapetus.
- [Риски условий использования](docs/RISKS.md): договорные риски Claude Code, Antigravity, Codex — граница и снижение; что CLI передают провайдеру, TLS-отличия шлюза, открытые вопросы.
- [Справка по `claude -p`](docs/CLAUDE-PRINT.md): опции и тонкости неинтерактивного режима (вывод, разрешения, контекст, сессии, процесс) для второго этапа — свой TUI, headless.
- [Окружение агента как на runner](docs/ENVIRONMENT.md): что агент получает с runner, что остаётся в контейнере session; решение по сетевым вызовам агента, идеи на будущее, полная поддержка MCP, отвергнутое.
- [Полномочия агента](docs/PRIVILEGES.md): что агент может в контейнере session и на runner по пробам стенда, риски и принятые решения.
- [Открытые вопросы](.claude/docs/QUESTIONS.md): решения, которые ждут ответа пользователя; ответ переносится в документ по теме, вопрос удаляется.

# Работа

- **Документация — источник истины.** Решение пользователя сразу вноси в документ из списка. Код, расходящийся с документацией, — повод спросить, а не молча выбрать одно из двух.
- **Запрет: ссылаться на документацию в комментариях кода** — документы меняются отдельно от кода, ссылка устареет. Комментарий объясняет сам, без отсылок.
- **Отвергнутые варианты не предлагай снова:** хуки Claude Code и MCP как механизм перехвата, отключение встроенных инструментов, runner рядом с session, резервную session, привязку ключа Claude Code к устройству. Последнее слово пользователя главнее раннего.
- **Факты о Claude Code — из документации и проверки, не по памяти:** поведение проверяй на работающем Claude Code и указывай версию.
- **Секреты проекта не попадают в репозиторий и журналы:** токены Claude Code, `GITHUB_TOKEN`, ключ центра сертификации SSH, ключ шифрования токенов, `.env`.
- **Полный прогон — один раз, когда все изменения задачи сделаны:** `scripts/check.sh` — `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo deny check` (уязвимые, заброшенные, отозванные крейты и лицензии) и тесты в `docker/docker-compose.test.yml` с именем проекта по каталогу рабочей копии, затем `down -v`. Голый `cargo test --workspace` полным прогоном не считается: медленные и случайные тесты выключены в нём проверкой `RUN_SLOW_TESTS`. Падения правятся, и прогон повторяется до зелёного; только после этого задача сдаётся. По ходу работы — только тесты затронутого модуля (`cargo test -p <крейт> <фильтр>`).
- **Устройство кода.** Две программы на Rust: `orbit` (`server`, `session`) и `waldo` (`worker`, `runner`) — только бинари; домены — модули `server`, `session` и `worker`, `runner`. Корень домена — `<домен>.rs`: роль, подмодули, `Args`, `run`; остальное — в каталоге `<домен>/`. Наружу домен отдаёт только `Args` и `run`, кроме входов, которые `main.rs` вызывает до разбора CLI или вместо него (оболочка `bash` и `drop-exec` у session) — иначе соседний домен дотянется до чужих внутренностей. Общее для программ — в `nerve`. Зеркальные части (`control`, `data`, `fs`, `exec`, `terminal`) называются одинаково с обеих сторон.
- **Формат.** Rust — по `rustfmt.toml`, остальные файлы — по `.editorconfig`. Правленый `.rs` форматирует хук Claude Code из `.claude/settings.json` — отдельный `cargo fmt` после каждой правки не нужен. Неотформатированный Rust не пройдёт коммит: его отклоняет `.githooks/pre-commit`; в новой рабочей копии без хука подключи его: `git config core.hooksPath .githooks`.
- **Lint'ы.** Уровни заданы в `[workspace.lints]` корневого `Cargo.toml`, каждый крейт подключает их `[lints] workspace = true`. Запрет: глушить lint через `#[allow]`; исключение — `#[expect(lint, reason = "…")]` с причиной: `expect` сам станет ошибкой, когда исключение перестанет быть нужным.
- **Документы и комментарии — на русском.** Технические термины и идентификаторы — как есть.

# Тесты

Тестируем только самое необходимое: то, что не гарантируют компилятор и типы и чья поломка дорого обходится. Тест оправдан тем, что его падение что-то значит.

- Что тестировать: безопасность (проверка сертификатов, маскирование секретов, токен вне журналов), сохранность данных (кэш FUSE, проверка хешей, автокоммит клона) и разбор чужих данных (SSE, postcard, вызовы оболочки агента). Остальное — только регрессионным тестом на найденную ошибку.
- Не тестировать геттеры, конструкторы, тривиальные преобразования, derive, сторонние крейты и то, что гарантирует компилятор. Тест, который мешает менять код и не стережёт перечисленное выше, удаляется.
- Запрет: тест, который не может упасть. Прежде чем считать тест готовым, внеси в код поломку, которую он должен ловить, и убедись, что он падает.
- Не ослабляй тест, чтобы он прошёл: падение — повод разобраться.
- Запрет: менять архитектуру ради тестов — новые слои, трейты для моков, лишний публичный API. Края подменяй настоящим кодом: сервер на `127.0.0.1:0`, `tokio::io::duplex`, временные каталоги.
- Время — `tokio::time::pause()`, а не настоящие паузы.
- `proptest` — для разборщиков чужих данных: любое разбиение входа даёт тот же результат, мусор — ошибка, а не паника.
- Имя теста — фраза о правильном поведении без префикса `test_`; сообщение падения называет нарушенное утверждение.
- Запрет: тесты в `src/`. Тесты лежат в `tests/` рядом с `src/` зеркалом дерева модулей: тесты `src/a/b.rs` — `tests/a/b.rs`, модуль подключает их строкой `#[cfg(test)] #[path = "…"] mod tests;`; заготовки тестов — там же. В крейте `autotests = false`, явный `[[test]]` — только для проверок собранной программы через `CARGO_BIN_EXE_*`.
